Take [the shared contract](00-contract.md). Deliver a locally usable spatial store whose map, last-seen observations and pending localization can be exercised without hardware. Reuse Mac transport, dock vision, private per-robot SQLite and current retention controls. Expose typed data to planning and speech only after identity, freshness and frame validation.

## Work in this order

1. **Make one typed pose reader.** Add `HttpHead` pose consumption using the established authenticated transport. Validate the `robot_id`, supported version, scalar bounds, quality, strictly increasing identity-bound sequence and freshness. Bind a local receipt time. Treat boot/origin change, missing pose, older body or head, clock reset, and negative or excessive values as observable stop conditions for current planning. Keep old ordinary robot paths usable. The pose reader holds no actuation lease.
2. **Calibrate the fixed camera.** Reuse the repo checkerboard capture and camera calibration tools. Pin intrinsics to the captured resolution and lens, then record distortion, rotation, height, origin, calibration identity and units. Verify image-to-ground projection using targets at measured locations and with horizon, crop and grazing-ray rejection. Limit inverse perspective mapping to a validated visible floor region. Keep calibration files private if they contain real space imagery.
3. **Anchor a real frame.** Use known AprilTag family, ID, physical size and measured placement per robot/dock. Reuse the repository’s fiducial detection and pose work. Accept a stationary observation only with ordered fresh JPEG metadata and its corresponding stationary poses, same body origin/camera boot, and a valid motion epoch. Bracket the capture with fresh poses and bound expected image lag using measurements from 30. Reject tag ambiguity, weak geometry, reprojection errors and inconsistent transforms. Apply validated `map → odom` corrections while keeping the body’s local `odom` continuous. Discard mappings across pickup until re-anchored. [REP-105](https://www.ros.org/reps/rep-0105.html), [AprilTag upstream](https://github.com/AprilRobotics/apriltag)
4. **Record only supported spatial evidence.** Start with 20 mm occupancy cells and clamp obstacle log odds to ±4. Use fresh appropriate readings for observed free/occupied updates. Represent unknown, stale and out-of-calibration cells explicitly. Keep floor safety in a separate layer, and keep CliffGuard as the independent authority. Preserve keyframes or safe viewpoints with current robot/origin, pose, time, uncertainty and provenance. An image or a tag alone cannot free a corridor.
5. **Persist with existing memory lifecycle.** Add a backward-compatible schema with per-robot identity, observation/anchor timestamps, source frame identity, normalized coordinates and uncertainty. Use transactions for observations and pose-dependent updates. Preserve deletion and retention behavior, including tombstones, with concurrent writes and restarts. Separate live sighting, historical location, stale, unknown and invalid origin. Define the read API and fixture with 60. Avoid retaining raw frames where the existing policy only calls for observations.

## Current source contract and open physical gates

These commissioning steps are requirements, not evidence of completed physical localization.

* `HttpHead.pose_status()` reads authenticated `GET /api/pose`. The Mac operator diagnostic is `GET /v1/robots/{robot_id}/pose` in `register_spatial_pose_route()`. Availability means a diagnostic reply exists, not usable odometry; `local_odometry_continuous` is a separate fence verdict. `source_age_ms` is null because the body clock is not synchronized to the Mac. This diagnostic reports `needs_reanchor=true`, `map_anchored=false` and no navigation, motor, charging or physical acceptance authority.
* `PoseFence`, `PlanarTransform` and `FloorProjectionCalibration` provide software validation, frame composition and pixel projection. `SpatialRuntime.bind_qualified_grid()` accepts a supplied anchor, calibration and optional map-to-odom transform; it does not measure or certify them. `SpatialGrid` implements 20 mm cells, bounded log odds and expiring support. `GET /v1/robots/{robot_id}/spatial/grid` is a read-only summary, not a permit.
* `SpatialMemory.attach()` currently accepts odom-frame observations without an anchor ID; `last_seen()` enforces the same boundary. Durable map-frame observations remain unsupported until the stationary JPEG/pose bracket and measured tag anchor producer exist. `GET /v1/robots/{robot_id}/spatial/memory?object_key=key` reads per-robot recall with hardware memory consent and private-memory revision/origin rechecks, never granting movement or asserting arrival.
* **OPEN / physical HOLD:** measured camera intrinsics and mounting, stationary capture-clock mapping, ten physical re-anchor trials, projection error across the usable desk, wheel slip, stopping envelope and eight-sensor coverage remain commissioning gates. Replay and host APIs do not establish these measurements. Require individual measured receipts before marking acceptance below passed.
