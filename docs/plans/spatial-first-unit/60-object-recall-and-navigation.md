Take [the shared contract](00-contract.md). Deliver the normal user flow from an observed object to a recalled target location, a qualified route, and a verified or explicitly unverified arrival. ## Work in this order

1. **Qualify object observations.** Compare existing visual detection/reuse with the optional local OWLv2 Base Patch16 Ensemble. Pin exact model revision, checksum, license, runtime and tested Mac resource budgets before inclusion. Reuse existing preprocessing and scheduling where compatible. Prefer a smaller existing detector if it meets the same object and timing criteria. Use at most one bounded local inference job. Record latency and false positives for keys and wrapped candy in varied lighting and hard negatives. Give voice and safety precedence and keep fixture tests offline. [OWLv2 model card](https://huggingface.co/google/owlv2-base-patch16-ensemble)
2. **Resolve a truthful target.** Query only the correct robot’s store. Keep a live confirmation, last-seen object, user-reported location and unknown state distinct in the result data. Offer last-seen time and uncertainty when the object is stale. Require supported camera-to-floor projection for metric goals. If the target has moved or is occluded, perform a bounded search from previously reachable viewpoints. Expire the request when its deadline, session, identity or origin changes. Return no current sighting when search cannot confirm one. The current controller consumes one proposed viewpoint per job; it must not imply complete coverage when further candidates remain. A definite negative on the last eligible viewpoint may return `not_found_after_search`, with the historical sighting timestamp; camera loss or inconclusive inference cannot establish exhaustion. A label detection without metric projection reports `target_seen_unverified_location`, never arrival. Physical confirmation requires the qualified stationary capture producer and mapped capture clock; synthetic replay does not supply that proof.
3. **Plan only through supported travel.** Use a small deterministic A* search over guide 50’s grid, bounded by state/deadline and qualified safe cells. Inflate obstacles for the measured footprint, swept turns, localization error and stopping margin. Reject unknown or stale support, unsafe turns, invalid map anchors or unreachable target approaches. Preserve established floor-edge and bumper policy. Plan a coarse observation pose around 180 mm from the target and consider a 60–80 mm approach only after hardware and view calibration establish usable margins. Keep those numbers configurable hypotheses until qualified.
4. **Execute a cancellable sequence.** Revalidate local status, request identity and safety geometry before each bounded motion request using the existing control owner. The controller rechecks the exact proposed edge against a fresh snapshot, including both inflated footprint disks and swept turn clearance; a new map cannot extend the original proposal deadline or replace its identity. Recheck after pose and health awaits, require a connected fresh authenticated camera from the anchored head boot in hardware, and reject unplanned final turns. Honor body faults and watchdog, user STOP and the active turn’s cancellation. Invalidating the map epoch, camera or detector during a plan triggers a deterministic bounded stop and clears old goal state. No unattended automatic reverse or blind spin. Near the target, require a fresh confirmed view and correct identity/location geometry before reporting arrival. Keep manipulation separately authorized and guarded. Record a finite reason for every stop, timeout or search result.
5. **Verify the whole story.** Replay object discovery, remembered location from a moved starting pose, physically moved or hidden object, wrong robot, drift, false detection, lost pose and STOP. Use test clocks and an audited fake actuator. Feed real physical outcomes back to the verification ledger after safe fit and commissioning.

## Detector candidate provenance and qualification (DRX-386)

Evaluation only; no model installation, runtime selection, or physical qualification is implied.

* Google OWLv2 Base Patch16 Ensemble: [immutable candidate checkpoint](https://huggingface.co/google/owlv2-base-patch16-ensemble/blob/27d9485a27e88c5f0435d0ed8382dcb3b911ab46/model.safetensors), revision `27d9485a27e88c5f0435d0ed8382dcb3b911ab46`, publisher-declared SHA256 `e1e130b9e404cf91a75ad45644c1da9d7fa5284085eecc864266a6923efb99e7`, approximately 620 MB for safetensors, [Apache-2.0 model declaration](https://huggingface.co/google/owlv2-base-patch16-ensemble). The digest is upstream metadata, not a locally verified download. Pin and hash processor/tokenizer/config files and runtime dependencies separately before use.
* Compare [OWL-ViT Base Patch32](https://huggingface.co/google/owlvit-base-patch32), [OWLv2 Base Patch16](https://huggingface.co/google/owlv2-base-patch16) and [Grounding DINO Tiny](https://huggingface.co/IDEA-Research/grounding-dino-tiny) on the same held-out frames. These model cards declare Apache-2.0; the nonensemble OWLv2 checkpoint is not inherently a smaller inference architecture. Do not claim Mac latency or small-object accuracy from model names or published benchmark scores.
* The existing optional Ultralytics YOLO-World adapter is the comparison baseline, not an implicitly MIT-licensed dependency: [Ultralytics licensing](https://www.ultralytics.com/license) and [original YOLO-World GPLv3 license](https://github.com/AILab-CVC/YOLO-World/blob/master/LICENSE) are separate. Review the exact installed library, weights and auxiliary text encoder before distributing a combined product. Do not copy GPL/AGPL implementation into MIT-owned source.
* Existing `YoloWorldVision` checks for a local file, not its digest; `vision` extra specifies a version range. Operator `object_detector_qualified` is not checkpoint identity. Local file existence also does not prove that text encoder initialization is offline. Use preprovisioned, verified assets and test cold startup with network disabled; ordinary CI must use local synthetic fixtures without downloading any model.
* Existing YOLO prediction implicitly applies upstream confidence filtering before the adapter sees results. A returned empty list is a view-specific no-detection result, not physical absence. Calibrate the backend candidate floor and decision thresholds separately on held-out positives and hard negatives (foil, reflective metal, USB connectors, printed key images, partial occlusion, poor lighting); never treat a numerical score as a calibrated probability of target identity. Keep uncertain outcomes distinct from negatives, and do not loosen movement or arrival gates.
* Record cold and warm latency, queue rejection, peak process memory, system memory pressure and swap on the actual Mac while Xiaozhi voice and live video run, with one detector job and stale/cancelled results discarded. The 250 ms frame freshness bound includes inference; the two-second timeout is not an extension of that freshness bound. Do not install multiple always-resident detectors or extend freshness just to make a benchmark pass. The physical stationary capture clock remains a separate prerequisite.

## Current source contract and open physical gates

* `POST /v1/robots/{robot_id}/navigate` is an operator endpoint returning HTTP 202 for a submitted or deferred job, not an arrival receipt. Its strict request model accepts `label`, `goal`, `goal_heading`, `start` and `heading`; coordinates are grid cell indices rather than millimetres. Optional `defer_on_voice` is a query parameter. `Coordinator.navigate()` requires `motion_enabled` and `spatial_navigation_qualified`, rejects dock inhibition, and in hardware requires a map-to-odom transform. Hardware object navigation additionally requires private memory consent.
* `plan_route()` and `revalidate_route_step()` check proposals and edges, not actuator permits. Coordinator execution remains subject to local health, STOP, identity and motion authority. `tests/test_first_unit_navigation_replay.py` uses synthetic evidence and a fake actuator, not physical arrival.
* **Implemented refusal, not completed physical object confirmation:** after the observation route, the hardware branch supplies an internal `rejected` observation with reason `camera_capture_clock_unmapped` until a qualified stationary capture producer is integrated. `summarize_search_observation()` exposes this as `status=no_current_sighting`, with the same reason and `arrived=false`, `target_observed=false`, `search_exhausted=false` and `physical_acceptance_pass=false`; job completion is not object arrival. It does not substitute Mac JPEG receipt time or ESP32 completion time for mapped capture time. Synthetic snapshots exercise downstream confirmation only. Detector qualification and a valid route cannot waive this refusal.
* **OPEN / physical HOLD:** actual Mac detector accuracy and latency, calibrated swept footprint and loaded cliff stopping, ten physical re-anchors, ten remembered-object returns and moved/occluded-target negative trials require measured receipts. The 9/10 re-anchor and 8/10 return figures below are requirements, not scores. Preserve independent gripper and docking qualification.
