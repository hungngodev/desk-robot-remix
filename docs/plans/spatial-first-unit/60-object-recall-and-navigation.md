# Object recall, reachable goals and safe route execution

Take [the shared contract](00-contract.md). Deliver the normal user flow from an observed object to a recalled target location, a qualified route, and a verified or explicitly unverified arrival. Start with replay and simulated transport. Guide 50 supplies spatial reads. Guide 40 supplies live turn and cancel identity. Guide 90 connects the approved path to the existing Mac control entry points.

Own the bounded detector worker, goal selection and route logic in scoped Mac modules under `code/laptop/src/desk_robot/` and their direct tests. ## Work in this order

1. **Qualify object observations.** Compare existing visual detection/reuse with the optional local OWLv2 Base Patch16 Ensemble. Pin exact model revision, checksum, license, runtime and tested Mac resource budgets before inclusion. Reuse existing preprocessing and scheduling where compatible. Prefer a smaller existing detector if it meets the same object and timing criteria. Use at most one bounded local inference job. Record latency and false positives for keys and wrapped candy in varied lighting and hard negatives. Give voice and safety precedence and keep fixture tests offline. [OWLv2 model card](https://huggingface.co/google/owlv2-base-patch16-ensemble)
2. **Resolve a truthful target.** Query only the correct robot’s store. Keep a live confirmation, last-seen object, user-reported location and unknown state distinct in the result data. Offer last-seen time and uncertainty when the object is stale. Require supported camera-to-floor projection for metric goals. If the target has moved or is occluded, perform a bounded search from previously reachable viewpoints. Expire the request when its deadline, session, identity or origin changes. Return no current sighting when search cannot confirm one. The current controller consumes one proposed viewpoint per job; it must not imply complete coverage when further candidates remain. A definite negative on the last eligible viewpoint may return `not_found_after_search`, with the historical sighting timestamp; camera loss or inconclusive inference cannot establish exhaustion. A label detection without metric projection reports `target_seen_unverified_location`, never arrival. Physical confirmation requires the qualified stationary capture producer and mapped capture clock; synthetic replay does not supply that proof.
3. **Plan only through supported travel.** Use a small deterministic A* search over guide 50’s grid, bounded by state/deadline and qualified safe cells. Inflate obstacles for the measured footprint, swept turns, localization error and stopping margin. Reject unknown or stale support, unsafe turns, invalid map anchors or unreachable target approaches. Preserve established floor-edge and bumper policy. Plan a coarse observation pose around 180 mm from the target and consider a 60–80 mm approach only after hardware and view calibration establish usable margins. Keep those numbers configurable hypotheses until qualified.
4. **Execute a cancellable sequence.** Revalidate local status, request identity and safety geometry before each bounded motion request using the existing control owner. The controller rechecks the exact proposed edge against a fresh snapshot, including both inflated footprint disks and swept turn clearance; a new map cannot extend the original proposal deadline or replace its identity. Recheck after pose and health awaits, require a connected fresh authenticated camera from the anchored head boot in hardware, and reject unplanned final turns. Honor body faults and watchdog, user STOP and the active turn’s cancellation. Invalidating the map epoch, camera or detector during a plan triggers a deterministic bounded stop and clears old goal state. No unattended automatic reverse or blind spin. Near the target, require a fresh confirmed view and correct identity/location geometry before reporting arrival. Keep manipulation separately authorized and guarded. Record a finite reason for every stop, timeout or search result.
5. **Verify the whole story.** Replay object discovery, remembered location from a moved starting pose, physically moved or hidden object, wrong robot, drift, false detection, lost pose and STOP. Use test clocks and an audited fake actuator. Feed real physical outcomes back to the verification ledger after safe fit and commissioning.

## Acceptance

- Require stable deterministic plans for known corridors, no routes through unknown support, rejection of undersized swept turns and no commands from stale, cross-robot or cancelled requests. Exercise normal live entry wiring with the existing transport fake and run focused navigation tests plus `tests/test_stop_transport_failure.py` and `tests/test_grasp_feedback.py` from `code/`.
- On the qualified unit, pass at least 9/10 valid re-anchors with translation error at most 20 mm and 8/10 remembered-object returns from moved robot starting positions with the target stationary. Log starting pose, tag/calibration ID, final pose and fresh target evidence. Test moved and occluded targets separately. Require zero false arrivals and zero unsafe commands across the negative cases. Document each trial, practical replay and runner SHA.
