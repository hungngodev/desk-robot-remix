# Requirements, owned parts and the complete shopping list

Take [the shared contract](00-contract.md) and the [first-unit shopping checklist](../first-unit-shopping-agent-checklist.md). Deliver one auditable first-unit order list for the robot, its dock and the shared station. Every required feature needs an explicit row for owned stock, a purchase, a documented shared assembly, or a specific unresolved selection. The operator should be able to order the resolved lines while the remaining selections proceed.

## Own these changes

Own `docs/product-definition.md`, the related decision log entry, purchase input JSON and inventory, and the procurement generator and its tests when the current format misses a required row. Generate the existing shopping projections from their canonical inputs. Ask [70](70-fit-power-manipulation-and-dock.md) for measured mechanical and electric envelopes, [20](20-body-safety-and-odometry.md) and [30](30-sense-camera-and-interface.md) for signal and source evidence, and [90](90-integration-and-release-evidence.md) for cross-layer verification. Let those owners change their source. Preserve the current historical purchase records and distinguish their dates from a new quote.

## Work in this order

1. **Record the first-unit scope.** Update the canonical first-unit spatial scope and acceptance cross-reference using the user’s decision in [the contract](00-contract.md). Trace ordinary barge-in, object find and return, proactive interaction, manipulation, safe travel, dock, charging and the station. Use each existing product ID where possible. Browse current source where a row says implemented. Capture normal entry point, configuration, default enablement, tests and evidence. Create issue-sized tasks for source gaps in their owner’s guide or the authorized shared tracker.
2. **Count and reconcile.** Read photo inventory and the local first-unit count. Track the confirmed HiLetgo PAM8403 speaker amplifier boards, Adafruit MAX9814 microphone preamp, DRV8833 board, momentary capacitive touch sensor, DFRobot FIT0774 vibration motor and photographed reed module as separate parts. Preserve confirmed parts for suitable roles or spares with a reason. Count the red reed board once unless there is evidence of distinct boards. The Sense PDM input and selected I²S amp stay in the intended voice path. A photo supports identification. Record the bench count and exact revisions separately. Include usable cables, fasteners, adapters and tools where the build requires them.
3. **Resolve each selected part.** Start with the existing canonical 49 parent roles and the 14 linked rows. Confirm per-unit quantities, station-once quantities, child-vs-parent ownership and fleet totals without double-counting. Add missing navigation roles, such as an encoder or bracket if the candidate needs one, through the canonical inputs. For each exact seller SKU record component, revision, voltage/logic levels, peak/stall current where applicable, connector/pinout, dimensions, supplied items, pin and power budget, stock, delivery territory and checked date. Compare common same-feature public builds and primary manufacturers’ documents. A claim of common usage should have actual example builds and the suitability reason. Canonical choices and verified alternatives should show their tradeoffs in price, fit, availability and code reuse.
4. **Close the order without making calibration a general prerequisite.** Mark each line as reuse, order, bench sample, conditional or unresolved with a concrete reason. Identify mount height, calibration parameters and measured thresholds as post-delivery work where the component choice is settled. Preserve specific release gates for energized packs, chargers, loaded motion and other already-gated hardware. Give each gated line a named dependency, the least expensive valid way to obtain its evidence, and a bounded choice between real options. Use the existing pilot output for already approved low-energy evaluations. Never label the pilot as the entire order.
5. **Price the complete order.** Capture exact USD unit price, quantity, shipping, tax, discounts, already-paid costs and total delivered by seller with time and location of the quote. Show the amount left under the cap after real prior spend. Keep unknown totals explicit. If no conforming selection meets the cap, document the closest supported cost and each line driving the overage. Preserve every required part and get the budget or design decision from the operator.
6. **Verify the buy link and its use.** Resolve exact listings, verify option selectors and packaging quantity, check repo role ownership, and walk from each selected BOM row through its harness/manual role or live software entry point. Mark passive stock with its assembly role. Record each active component’s driver, hardware profile and exercised behavior. Refresh the purchase projections and run the current receipt verifier.
