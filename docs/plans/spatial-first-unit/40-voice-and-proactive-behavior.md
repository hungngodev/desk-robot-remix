# Human interruption, proactive interaction and expressive behavior

Take [the shared contract](00-contract.md). Make the robot react to real changes and deliberate contact while ordinary human speech can preempt any optional work. Reuse the continuous Xiaozhi audio session and existing acoustic arbitration. Keep proactive behavior on the live robot path and preserve each robot’s identity and settings.

## Own these changes

Own Mac voice and behavior policy in the established Xiaozhi server overlay, `conversation.py`, `multimodal.py` and `pet.py` where needed. Coordinate shared API registration with [90](90-integration-and-release-evidence.md). Guide 30 handles head queue and AEC firmware. Guide 50 stores witnessed observations. Guide 60 defines typed recall and navigation results. Ask those owners for fixtures and timing contracts.

## Work in this order

1. **Trace an ordinary turn.** Follow authenticated head PDM/VAD, the voice session, Mac turn and playback generation, TTS queue, Sense I²S stop and display. Find the currently active voice owner, settings and required compatibility paths before adding anything. Measure cancel dispatch, audio generation invalidation and interface fallback. Use a deterministic cut-in fixture to prove any actual gap.
2. **Make human VAD highest speech priority.** On the current authenticated turn, invalidate stale TTS generations, cancel optional capture and model work, release the acoustic lease and keep real new speech from the beginning. Retain recent audio only within existing consent and privacy limits. Recognize the new interrupted intent and deduplicate repeated VAD messages. Check new-utterance capture while preserving software echo rejection. Handle disconnect and renewals without restarting old audio. Keep STOP/disarm independent of the audio path.
3. **Connect event-driven awareness.** Reuse current authenticated sensor bursts, scene comparison, deliberate physical contacts, data age checks, shared audio floor and per-pet cooldowns from the live head. Merge closely related observations. Use the current camera path with one bounded optional job per robot and give direct requests priority. Check pet mode, quiet/consent, recent speech, cooldown, camera availability and robot identity at scheduling and immediately before any response. Release leases on exceptions and cancellation. Record actual observed change and its provenance. Use a brief permissible action or expressive face update when available.
4. **Separate dialogue from long-running tools.** Snapshot robot, session/turn, generation, motion epoch and deadline with each map, detector or recall request. A cancelled/obsolete result cannot speak, move, create fresh memory or claim a sighting. Use the existing authorized tool broker and one active talker. Keep normal conversation responsive with a busy, failed or unplugged detector. If the existing local option is insufficient, document the gap and evaluate optional upstream cloud session/tool behavior only under explicit opt-in. [Gemini Live session](https://ai.google.dev/gemini-api/docs/live-session), [Gemini Live tools](https://ai.google.dev/gemini-api/docs/live-tools)
5. **Verify expression with motion disabled.** Use the existing listening, thinking, speaking and quiet states. Test that declared speech and actual playback do not diverge on cancellation. Honor the current configured stagger and cooldown across pets. Per-robot callback state must withstand simultaneous triggers and reconnect without a wrong-pet action.
